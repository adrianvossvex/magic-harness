## What was built

**Modules** (`src/`):
- `books.js` — `addBook`, `listBooks`; `available` is computed live as `copies` minus active loans, so it never goes stale.
- `members.js` — `addMember`.
- `loans.js` — `checkout`, `returnLoan`, `listLoans`, `report`.
- Support: `store.js` (JSON load/save, id allocation, creates the file on first use), `dates.js` (UTC-safe date arithmetic), `validate.js` (input checks).

Every function takes one options object and an optional `data` property for the file path, which is how the CLI threads `--data` through.

**CLI** (`bin/library.js`): all seven commands, one JSON value on stdout for success (exit 0), `{ "error": ... }` on stderr and exit 2 for failures, exit 1 for unknown commands and missing options. I verified the exit codes by hand (unknown command → 1, missing `--title` → 1, business-rule failure → 2).

**Tests** (`test/`): one file per module plus `test/cli.test.js`, which spawns the real binary to check output, filters and exit codes. Total 26 tests.

**Docs**: `README.md` documents the modules, every command with a worked example, and the rules. I corrected one example whose printed output didn't match the state at that point in the sequence.

## Rules implemented
- Checkout fails on a missing book/member, no available copy, or a member already holding 3 active loans.
- Returns are fined 0.50 per day past the due date, capped at 20.00; on-time returns cost nothing; returning twice fails.
- Dates are `YYYY-MM-DD` strings with `today` defaulting to the current date.

One small thing worth flagging: Node's test runner treats every `.js` file under `test/` as a test file, so the shared `test/helpers.js` shows up as a passing entry with no assertions of its own.
