Design decisions worth flagging, since the brief leaves them open:

- **Single production file.** All logic lives in `bin/kv.js`; no `lib/` split, because the tests exercise the CLI end to end and a library would add an interface nothing depends on.
- **Frozen store schema**, since tests must fabricate expired entries by writing the file directly: a JSON object mapping key to `{ "value": string, "expiresAt": number|null }`, with `expiresAt` an absolute epoch time in milliseconds.
- **Argument parsing**: `--file` and `--ttl` are scanned out of the args anywhere after the command; the `--file=path` equals form is not supported. `--ttl` is only meaningful for `set` and ignored elsewhere.
- **Error/exit contract**: exit 1 for not-found, invalid key, invalid TTL and unreadable store; exit 2 for usage errors (unknown command, wrong arity). Exact messages `not found: <key>`, `invalid key: <key>`, `deleted`, and a usage block on stderr are specified verbatim.
- **Expiry**: an entry is expired when `expiresAt <= Date.now()`; `get` prunes and rewrites atomically, `del` prunes and treats it as missing, `list` filters without rewriting.
- **Atomic writes**: temp file in the same directory plus `fs.renameSync`.
