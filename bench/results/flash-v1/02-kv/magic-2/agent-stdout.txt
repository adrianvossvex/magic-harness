**What's there**

- `bin/kv.js` — CLI entry point: argument parsing, command dispatch, and output/exit codes. `node bin/kv.js <command> [args] [--file <path>]`.
- `src/store.js` — store logic: key validation, JSON read, and atomic write (temp file in the same directory → `fsync` → `rename`), plus expiry checks against absolute millisecond timestamps.
- `test/cli.test.js` — `node:test` suite that runs the CLI via `spawnSync` against a per-test temp store file.
- `package.json` — added `"test": "node --test"`, a `bin` entry, and a description.
- `README.md` — documents every command, keys, exit codes, and the store file format.
- `.gitignore` — added `.kv.json` so local stores aren't committed.

**Behavior confirmed by tests and a manual smoke run**

Commands `set`/`get`/`del`/`list` behave as specified, including multi-argument values joined with single spaces, sorted `list` output, empty-store silence, absent-or-expired-key handling (`not found: <key>` on stderr, exit 1), invalid keys (exit 1), and unknown/missing commands (usage on stderr, exit 2). Expiry is covered three ways: an absolute timestamp asserted to be `now + ttl` in milliseconds, a real short-TTL wait, and a hand-written already-expired timestamp; reading an expired key prunes it from the file, and `list` prunes while filtering.

**Two decisions worth flagging**

`--file` and `--ttl` are extracted wherever they appear in the argument list, so `set k v --ttl 5` and `--file path set k v` both work. The tradeoff is that the literal value `--ttl` can't be stored as a value.

A missing key operand (e.g. `get` with no argument) prints usage and exits 2, since the spec only assigns exit 1 to *invalid* keys; exit 2 covers malformed invocation generally. I also fixed one bug found by the test run along the way: `set` was initially routing invalid keys through the usage path (exit 2) instead of the required exit 1.
