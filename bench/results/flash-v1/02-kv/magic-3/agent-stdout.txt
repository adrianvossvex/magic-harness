## What's there

**`bin/kv.js`** — argument parsing and command dispatch. `--file` defaults to `.kv.json` in the current directory and works before or after the command; `--ttl` applies to `set`. Output goes through `process.stdout.write`/`stderr.write` and the exit code is set via `process.exitCode` rather than `process.exit`, so piped output is never truncated (I verified a 300 KB value round-trips intact).

**`lib/store.js`** — store logic. The file is a JSON object of `{ value, expiresAt }` entries, where `expiresAt` is an absolute epoch time in milliseconds or `null`. Writes are atomic: serialize to a sibling temp file, then `renameSync` over the target. The store is held in a `Map` and serialized with `Object.fromEntries`, so keys like `__proto__` and `constructor` are stored as ordinary own properties rather than touching the prototype chain.

**Behaviors** match the spec: `set` prints nothing; `get` prints the value plus newline, or `not found: <key>` on stderr with exit 1 (and purges the expired entry from the file on read); `del` prints `deleted` or reports not found on stderr with exit 1; `list` prints non-expired keys sorted, nothing for an empty store; keys are validated against `/^[A-Za-z0-9_.-]+$/` (exit 1 on failure); unknown commands and usage errors print the usage text on stderr and exit 2.

**`test/kv.test.js` and `test/ttl.test.js`** — run the CLI via `spawnSync` against temp store files. They cover every command, all error/exit-code paths, key validation, the default `.kv.json` location, that no temp files are left behind, and TTL expiry via three angles: a short real TTL (`--ttl 0.1` then a sleep), an already-expired timestamp seeded into the file (a controllable fake clock for the read/purge path), and an invalid `--ttl`.

**`README.md`** documents each command with examples, the options, key rules, and the exit-code table. I also added `.kv.json` to `.gitignore` so the default store doesn't get committed.

One judgment call worth flagging: `--ttl` and `--file` are extracted from anywhere in the argument list, so a value that is literally the string `--ttl` or `--file` on a `set` would be consumed as a flag rather than part of the value. Every other token, including ones starting with `--`, is treated as a positional value.
