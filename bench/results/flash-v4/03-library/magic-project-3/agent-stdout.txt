**What I built**

`bin/library.js` is table-driven: a `commands` object maps each command name to `{ required, optional, flags, numbers, run(values) }`. Adding a command later is one table entry — parsing, per-command option validation, `Number()` coercion, output and exit-code selection are all shared. `add-book`, `add-member` and `list-books` are implemented; `checkout`/`return`/`list-loans`/`report` are deliberately left out for the `cli-loans` task and currently fail cleanly as unknown commands (exit 1), which is correct for this task.

Key behaviours:
- Success writes `JSON.stringify(value)` + newline to stdout, exit 0, nothing else.
- Failure writes `{"error":message}` + newline to stderr; exit 1 for usage errors (missing command, unknown command, unknown option, a valued option with no value, unexpected extra positional), exit 2 for anything thrown while running (including a `--data` path that can't be created).
- `--data` is extracted during parsing and applied via `setDataPath` before the command runs, so it works before or after the command name.
- Options listed in `numbers` go through `Number()` and are validated by the module, so `--copies abc` exits 2 while omitting `--copies` uses the default of 1.
