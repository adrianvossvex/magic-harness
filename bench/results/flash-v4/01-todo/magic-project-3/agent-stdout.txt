## What I did

Added a new file `test/store.test.js` (left `test/todo.test.js` untouched, so the existing "add and list" test stays exactly as it was). Each test builds its own fresh `createStore()`, and the cases cover the contract in the design document:

- `count()`: 0 on a new store, increments by one per `add`, decrements by one after a successful `remove`.
- `toggle(id)`: flips `done` false→true, flips back to false on a repeated call, returns the same object `add` produced (asserted via identity plus `id`, `text`, and `done`), and the change is visible through `list()`.
- `toggle(unknownId)`: throws with `assert.throws(() => s.toggle(99), /Unknown id/)` and the store is verified unchanged afterwards via `count()` and the listed item's `id`/`text`/`done`.
- `remove(id)`: returns `true`, shrinks `count()`, and the removed item is gone from `list()`; a second `remove` with the same id returns `false`.
- `remove(unknownId)`: returns `false` and leaves `count()` and `list()` intact.
- `list()` copy semantics: emptying and mutating the returned array leaves `count()` and the store's contents unchanged.

Ids and text values are asserted to pin the interface, and no test asserts anything about id reuse after a removal.
