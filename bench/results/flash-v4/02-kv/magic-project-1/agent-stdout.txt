**Design highlights (all decisions frozen in the design doc):**
- Layout: `bin/kv.js` (thin entry point) → `src/cli.js` (parsing, command dispatch, output, exit codes) → `src/store.js` (load/save, expiry helpers, key validation). ESM, synchronous fs, no dependencies, no build step.
- Store format pinned so tests can seed hand-written files: `{"keys": {"k": {"value": "…", "expiresAt": <epoch ms>|null}}}`; missing file = empty store; corrupt file → `cannot read store: <path>`, exit 1, no write.
- Atomicity: pretty-printed JSON written to `<basename>.tmp-<pid>-<random>` in the same directory, then renamed; temp file cleaned up on failure so no leftovers remain.
- Expiry semantics: `now` threaded as a parameter (fake-clock friendly), `get`/`del` treat expired as missing and prune the entry from the file, `list` filters but never writes, and a never-existing key never creates the file.
- Argument rules documented precisely, including that only `--file` (global) and `--ttl` (set-only, fractional seconds allowed) are flags, plus the full exit-code table (0/1/2) and exact stderr strings.
- `npm test` is `node --test test/*.test.js` — the explicit glob matters because a bare `node --test` would collect the shared `test/helpers.js`.
