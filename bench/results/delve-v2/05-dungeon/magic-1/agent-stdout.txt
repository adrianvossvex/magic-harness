## What's there

**Deterministic core** (`src/`, pure ES modules, no dependencies, no DOM/clock/`Math.random`):
- `rng.js` — mulberry32; reproduces the spec's golden values for seed 123 exactly (`0.7872516233474016`, `0.1785435655619949`, `0.49531551403924823`), with a readable/writable 32-bit `state`.
- `map.js` — 60×30 levels, 6–12 non-touching rooms, L-corridors, verified 8-directional reachability, `start` in the first room, `stairs` in the farthest room by centre distance, `>` only below depth 5.
- `fov.js` — the given Bresenham algorithm, radius in Euclidean distance, walls visible only where the line reaches them.
- `path.js` — 8-directional BFS, minimal step counts, `blocked` tiles impassable except the target.
- `game.js` — state, all six actions, the monster table and turn order, combat, items, equipment, level-ups, `serialize`/`loadGame`/`hash`/`applyKey`/`runScript`.

**Browser side**: `index.html` (exact cdnjs 0.160.0 script tag, relative module script, HUD `#hud` with `HP 30/30 · Depth 1 · Turn 0` plus level/xp/gold, `#log`, pack panel on `i`, help on `?`, title/death/victory overlays, `?seed=`/`?script=` params, `window.game`) and `src/renderer/` — instanced floors and walls with height, grid texture, stairs marker, distinct low-poly meshes with glyph labels for the player and every monster type, item shapes including the amulet torus, unexplored tiles hidden / explored dimmed / visible lit, a light that follows the player, a smoothly easing camera above and behind, hit flashes, screen shake, kill bursts, movement tweens, and WebAudio beeps armed on the first real key press. The renderer never calls `Math.random` (effects use a deterministic hash) and only ever reads state.

## Checks I ran

- `npm test` — 70 tests across `rng`, `map`, `fov`, `path`, `game`; includes a cross-check of path lengths against an independent BFS and a full read of the monster table.
- A 5,000-level sweep (1,000 seeds × 5 depths): room counts always 6–12, every floor tile reachable, stairs glyph correct, generation never fell back to the fixed layout (~0.4 ms per level).
- `screenshot` on `index.html` in several states: title screen, scripted run, a scripted kill (particle burst visible), a descend to depth 2, and a scripted death showing the "You died" screen — 0 console messages, 0 errors in each.
- A temporary in-page probe (since the tool can't send keys) confirmed the key handler: arrows move, `i` toggles the pack, `?`/Escape toggle help, `R` is inert mid-game, an invalid item index costs no turn. That probe was removed afterwards.

## Decisions where the rules left room (all written up in README.md)

Item `name` is the plain kind except the amulet ("Amulet of Yendor"); monsters and items share one id counter so no id ever repeats; `pickup` spends a turn only when something was actually picked up (a full pack costs nothing); one log line per gold pile; the stairs tile is kept clear for the amulet; fixture levels set `stairs` to the first `>` and `start` to the player; `visible` is sorted by y then x so hashes are stable; the rng's 32-bit state lives in `state.rngState`, which is what makes `serialize`/`loadGame` (and hashing) capture future behaviour. Generation retries with the continuing rng stream if a layout comes out invalid, with a fixed six-room layout as an unreachable-in-practice last resort.
