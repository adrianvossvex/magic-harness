**What I built**

- `bin/kv.js` — argument parsing and command dispatch (`set`, `get`, `del`, `list`). It strips `--file` / `--ttl` options anywhere in the argument list, and supports `--` to force the rest to be treated as positionals, so values that start with a dash still work (`set opts -- --ttl` stores the literal `--ttl`).
- `src/store.js` — load/save of the JSON store and the expiry check. Writes go to a temp file in the store's directory and are then `rename`d over the target, so a crash never leaves a partial file. A missing store file is treated as empty.
- `test/kv.test.js` — runs the real CLI as a child process against a fresh temp file per test.
- `README.md` — documents every command, both options, key rules, exit codes, and the store format.
- `package.json` — added `"test": "node --test \"test/**/*.test.js\""` and a `bin` entry; `.gitignore` now ignores the default `.kv.json`.

**Behavior details worth flagging**

- Exit codes: `0` success, `1` for missing/expired key and invalid key, `2` for usage errors (unknown or missing command, bad `--ttl`). Unknown commands print the usage block on stderr.
- `get` on an expired key deletes it from the file before reporting `not found`, so the stale entry doesn't linger. `list` filters expired keys out but leaves them in the file.
- Store shape is `{ "version": 1, "data": { <key>: { "value": ..., "expiresAt": <epoch ms|null> } } }`.
- `set <key>` with no value stores an empty string, since the value is the join of zero remaining arguments.
