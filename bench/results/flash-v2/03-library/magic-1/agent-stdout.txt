**Design decisions worth knowing**

Each module call reads the whole file, mutates it and writes it back, so commands are independent processes. Every function takes an optional trailing options object `{ data }` for the file path; it defaults to `data/library.json` resolved against the current working directory, which is how `--data` is threaded through. A book's `available` count is derived from `copies` minus its active loans rather than stored, so the file can't drift out of sync; `available` appears in every book a command prints. Ids are `max(existing id) + 1` per entity type, which gives 1, 2, 3, … in order without persisting counters.

Exit codes follow the spec: `0` on success, `2` for domain failures (validation, unknown id, checkout rule violations, corrupt data file), and `1` for usage problems (unknown command, unknown option, missing option or missing option value). All failures print `{"error": "..."}` on stderr. Days late are computed in UTC on date strings, so there are no DST or timezone surprises, and fines are rounded to cents and capped at 20.00.
