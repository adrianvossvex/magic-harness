## What I built

**Modules** (`src/`)
- `books.js` — `addBook` and `listBooks`. Books are `{ id, title, author, copies, available }`; `available` starts at `copies` and moves as copies are checked out. `title`/`author` must be non-empty (trimmed), `copies` a positive integer.
- `members.js` — `addMember`, producing `{ id, name }`.
- `loans.js` — `checkout`, `returnLoan`, `listLoans`, `report`. Loans are `{ id, bookId, memberId, out, due, returned, fine }`. Enforces the three rules: no checkout without an available copy, no more than 3 active loans per member, 0.50/day late fine capped at 20.00, no double returns.
- `store.js` — the single JSON file (`data/library.json` by default), parent-directory creation, file creation on first use, per-collection id counters reconciled with existing records, and JSON-parse errors surfaced as command failures.
- `dates.js` — `YYYY-MM-DD` parsing, validation, `+N days`, and day differences. All arithmetic is in UTC so daylight saving can't shift a due date or a late count.
- `errors.js` — `LibraryError` (exit 2) vs `UsageError` (exit 1).

**CLI** (`bin/library.js`) implements every command and option. Success prints one JSON value on stdout, exit 0; command failures print `{ "error": ... }` on stderr, exit 2; unknown commands and missing options exit 1. One judgment call worth flagging: an option that is *present but invalid* (e.g. `--copies many`, `--copies 0`) exits **2**, since the spec reserves exit 1 for unknown commands and missing options only.

**Tests** (`test/`) — `books.test.js`, `members.test.js`, `loans.test.js` cover the modules directly, and `cli.test.js` runs the binary as a subprocess to check JSON output and exit codes. Each test uses its own temp data file. The `test` script is `node --test "test/*.test.js"` — the explicit glob keeps the shared `test/helpers.js` from being picked up as an empty test file.

**README.md** documents the storage format and id rules, every module function, every command with a runnable example, and the rules.
