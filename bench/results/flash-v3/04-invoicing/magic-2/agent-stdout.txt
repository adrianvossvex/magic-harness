## What was built

**Library modules** (`src/`):
- `money.js` — `parseMoney` (strict non-negative decimal strings, ≤2 decimals), `formatMoney`, `roundCents` (half up).
- `customers.js` — `addCustomer`, requires `@` in email.
- `products.js` — `addProduct`, price parsed to cents, `taxRate` integer 0–100 defaulting to 0.
- `invoices.js` — the full lifecycle: `createInvoice` (draft), `addLine` (line math with half-up rounding), `issue` (per-year `INV-<year>-<nnnn>` counter, due = issued + terms), `pay` (partials allowed, overpay rejected, auto-`paid`), `voidInvoice`, `listInvoices`, `getInvoice`.
- `report.js` — `aging` (five buckets by days past due) and `revenue` (per issue month).
- Supporting: `store.js` (single JSON file with `--data` override, ids/counters, in-memory cache), `dates.js` (UTC date arithmetic), `errors.js` (`UsageError`), `present.js` (cents → formatted-string JSON shapes, CSV export).

**CLI** (`bin/invoice.js`) — all 12 commands. Success prints one JSON value and exits 0; money fields are formatted strings. Domain failures print `{"error":"..."}` on stderr and exit 2; unknown command or missing required option prints usage and exits 1.

**Tests** (`test/`) — one file per module plus an end-to-end CLI test that spawns the binary and asserts exit codes, stdout/stderr JSON, and money formatting.

**Docs** — `README.md` documents the money/date rules, every module API, and every command with a real example. `package.json` now has `"test": "node --test"`.

## Notable implementation decisions
- **All money is integer cents end to end**, with integer arithmetic for parsing and rounding, so no floating-point drift creeps in.
- **Dates use UTC** so due-date math is timezone-independent; `today` defaults to the local current date throughout.
- **`store.load()` caches the parsed file in memory** so repeated calls in one process share object identity — a record returned by `createInvoice` reflects later `addLine`/`issue`/`pay` mutations. This also means the first use (even a read like `list`) materializes `data/invoicing.json` and its directory.
- **Ordering of validations is validate-before-mutate**, so a thrown error never leaves partially-mutated state to be persisted.
