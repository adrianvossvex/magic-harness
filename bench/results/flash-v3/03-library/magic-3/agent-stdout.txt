## What's there

**Modules** (`src/`, ES modules, no dependencies):
- `src/store.js` — JSON persistence. `load()` creates the data file on first use and returns a snapshot; `save()` writes it back (creating parent dirs); `nextId()` assigns per-type ids from 1. `setDataFile(path)` is how the CLI applies `--data`.
- `src/dates.js` — `YYYY-MM-DD` validation, `addDays`, `daysBetween`, local `todayISO`.
- `src/books.js` — `addBook`, `listBooks`.
- `src/members.js` — `addMember`.
- `src/loans.js` — `checkout`, `returnLoan`, `listLoans`, `report`, with the 3-active-loan limit, the 0.50/day fine capped at 20.00, and the double-return error.

**CLI** (`bin/library.js`): parses `--data` from anywhere in the argument list, validates each command's options against a small per-command schema. Success prints one compact JSON value on stdout, exit 0. Failure prints `{"error":"..."}` on stderr, exit 2 — or exit 1 for unknown command, missing required option, unknown option, or a missing option value. Invalid option values (e.g. `--copies abc`) are validation failures at exit 2, as are business-rule rejections.

**Tests** (`test/`, `node:test`): one file per module plus a CLI end-to-end file. Each test points the store at a fresh temp file via `test/helpers.js`, so nothing touches `data/library.json`.

**`package.json`** gained `"scripts": { "test": "node --test" }`; **`README.md`** documents the modules, every command with an example, the rules, and the tests.

## Verification
- `npm test`: 36 pass, 0 fail.
