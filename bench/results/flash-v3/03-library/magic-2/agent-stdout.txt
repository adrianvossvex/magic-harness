## What's there

**Modules** (`src/`, ES modules, zero dependencies):
- `src/store.js` — JSON persistence. Resolves the path (`data` option → `LIBRARY_DATA` env var → `data/library.json` relative to cwd), creates the file and any missing directories on first use, and repairs counters from existing ids.
- `src/dates.js` — `YYYY-MM-DD` validation and UTC-based day arithmetic (so DST never shifts a due date).
- `src/errors.js` — `LibraryError`, thrown for invalid input or broken rules.
- `src/books.js` — `addBook`, `listBooks`.
- `src/members.js` — `addMember`.
- `src/loans.js` — `checkout`, `returnLoan`, `listLoans`, `report`.

Each module function takes an optional `data` key naming the file, matching the documented option shapes (e.g. `addBook({ title, author, copies = 1, data })`). Ids are per-type counters starting at 1.

**CLI** (`bin/library.js`): commands print one JSON line and exit 0; failures print `{"error":"..."}` on stderr with exit 2; unknown command/missing option exit 1. A checkout decrements `available`, a return increments it; a late return stores a fine of 0.50/day capped at 20.00; a member is blocked at 3 active loans; double-return fails.

**Tests** (`test/`, `node:test`): `books.test.js`, `members.test.js`, `loans.test.js` (checkout limits, fines, cap, overdue filtering, report arithmetic), and `cli.test.js` (stdout JSON, exit codes, default path creation). `package.json` now has `"test": "node --test"`.

**README.md** documents the storage format, the rules, every module function, and every command with a worked example and its output.
