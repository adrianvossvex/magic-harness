**One judgment call worth flagging:** `add` previously derived ids as `items.length + 1`. That works only while nothing is ever removed — add "a" and "b", remove "a", then add "c", and the new item would get id 2, colliding with "b". Since `toggle` and `remove` look items up by id, a collision makes those methods operate on the wrong item, so I switched id generation to a `nextId` counter that increments per `add` and is never reused. Sequential adds still produce ids 1, 2, 3 exactly as before, so existing usage is unaffected; only the post-removal case changes, and that case was previously broken. The `ids stay unique after a removal` test pins this down. If you'd rather keep the literal old expression and accept duplicate ids, say so and I'll revert that line.
